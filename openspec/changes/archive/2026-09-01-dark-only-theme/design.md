# Design — one dark theme (#304)

## ADR 304 — Harmonic ships one theme, and Light retires as a removal

**Decision.** The app ships dark only. The light palette, the footer Theme menu,
the `theme` localStorage key, and the boot-time class gate are removed, not
defaulted: no class, attribute, or stored value selects a theme, and every rule
that was scoped `html.dark` or `html:not(.dark)` becomes a base rule. Dark's
computed values do not move in this change; the second locked order on #304
settles the finished graphite values in the running app under UI Craft revise
and is the only place a palette value changes.

**Why.** Two palettes split design attention and doubled every gate, extract,
and capture. A default flip would keep the second palette alive as dead weight
and keep the gates measuring a theme nobody ships.

**Consequences.** ADR 37 (the light ground is bone) and ADR 230 (theme repaint
preserves the mounted Diagnose workspace) describe retired behavior; their
records stay as history and this record supersedes them. The
`preserve-diagnose-theme-context` and `light-ground-bone` changes are not
archived here. The gated support-audit scenarios named `*-light` re-capture on the
one theme under the same scenario identities.

**Sanction.** Connor Griffin, issue #304, 2026-09-01: light theme retired by
operator decision.

## ADR 304 — Theme stories retire under sanction; cross-theme invariants re-base

**Decision.** Cockpit shell stories S3 (Theme opens a radio menu; choosing Dark
updates the rendered theme, checked state, persisted choice) and S10 (Theme menu
hover treatment) and Diagnose story S117 (theme repaint preserves the mounted
workspace) retire. Each retirement entry quotes the sanction above with its date.
Every story or assertion that today loops over `['light', 'dark']` keeps its Dark
half unchanged and drops the Light half; an assertion that only compared the two
themes to each other (theme-invariant geometry) is re-based to assert the Dark
values directly rather than deleted.

**Why.** UI Craft revise treats a story missing from the base as an unsanctioned
retirement until a named person rules it. Dropping the Light half of a paired
assertion is re-basing; dropping the Dark half would weaken a gate, which the
risk contract forbids.

## ADR 304 — Extract generators bind to the single token block

**Decision.** `mockups/diagnose-evidence-canvas.exploration/generate.py` and
`mockups/finding-evidence-routing.exploration/build.mjs` stop requiring a
standalone `html.dark {` block and `color-scheme: light` needle and instead
require exactly one `:root {` token block carrying the `--wk-*` roles. Their
corruption self-checks move with them. Both `--check` steps stay in CI unchanged.

**Why.** The drift gates exist to catch an extract measuring a retired theme;
the theme retiring is exactly the event they guard, so they move in the same
change or CI goes red, as it did on PR #303.
