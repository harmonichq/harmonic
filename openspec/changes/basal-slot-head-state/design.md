# Design — basal slot case-file head state

## ADR 103 — Basal case-file heads name their own verdict

### Context

ADR 25 established that a case-file verdict and its stageability are separate facts for the correction factor. Basal slot case files instead used one fixed non-asserting head, so a held slot and a no-data slot appeared as insufficient evidence despite their lane tile and explanation naming different states.

### Decision

For a basal slot that cannot stage, the case-file head reads the existing verdict wording produced for that slot's lane cell. The asserting branch remains unchanged. This keeps the panel and lane on one vocabulary without exposing backend engine statuses.

### Safe-start provenance

`AGENTS.md` declares the synthetic-only safe start:

```sh
uv run harmonic serve --no-fetch --db mockups/revise-e2e.synthetic/harmonic.sqlite --port 8876
```

The database is generated by `scripts/gen_revise_e2e_db.py` from fixed seed 620. Deterministic reads use `mockups/diagnose-workstation.synthetic/payload.json`, generated by `.claude/qa/gen_synthetic_fixtures.py` from a fixed seed. No live fetch or personal data is used.

### Boundaries

The asserting basal head remains out of scope because it is a separate action-bearing copy decision. The findings queue has its own status vocabulary and is unchanged.
