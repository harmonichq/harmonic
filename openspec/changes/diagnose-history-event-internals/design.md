## ADR 132 — Empty the history event header chip

The past-setting event view renders no text in the header's persistence chip.
It does not re-word the internal analysis generation because issue #166 may
retire or relocate this surface, while the neighboring scope already states the
meal-run count. The generation remains on the canvas and level `data-*`
attributes for coherence checks and is restored with the original clock header
when the user leaves the event view.

This records Connor Griffin's 2026-08-24 ruling to empty the chip rather than
invest in replacement copy. Issue #166 remains the sole owner of where past
settings are reported.
