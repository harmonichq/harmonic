# Design — Diagnose Occurrence roster keys

## ADR 101 — Roster keys follow the axis the roster is drawn on

### Context

The Diagnose case file renders Occurrences as a vertical roster. Its former
Left/Right stepping conflicted with the event-comparison chart's Left/Right
cursor: chart key events reached the document handler and moved both controls.
Selection also repaints asynchronously, replacing the roster button that had
focus.

The declared revise entrypoint is:

```sh
uv run harmonic serve --no-fetch --db mockups/revise-e2e.synthetic/harmonic.sqlite
```

The database is generated by `scripts/gen_revise_e2e_db.py` from fixed seed 620;
the replay payload is committed synthetic data. No live fetch is involved.

### Decision

ArrowDown advances and ArrowUp reverses the selected Occurrence within the
visible verdict roster, stopping at each end. The hint prints `↑ ↓`. Left/Right
are withdrawn rather than retained as aliases: Connor Griffin ruled on
2026-08-23, "the roster is drawn vertically; one key model per list."

The request carries the desired Occurrence id. The case-file render restores
focus only after the replacement response has completed and only when it
rendered that same selection. This avoids focusing the retained old roster
during the loading paint. A selection outside the evidence cap has no rendered
button and therefore remains an accepted unsupported focus-loss case.

The document handler bails out for an Up/Down event targeted in `#ec-chart`.
That guard is earned: the event chart is focusable in an event-aligned case file
alongside a selected roster row. No `filterOpen` guard is added. The invariant
is enforced by `push`, `popTo`, and `paintFilter`: moving off the root closes the
root-only Filter, while roster handling runs only on a factor frame.

### Consequences

The chart keeps its own cursor behavior, including Left/Right. The roster's
former Left/Right double-fire ends. Replay S11, S12, S78, S79, and S80 preserve
the new model and its sanctioned retirement.
