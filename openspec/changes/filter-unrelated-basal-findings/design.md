# Design — filter unrelated basal findings

## ADR 81 — Sliced findings never retain an earlier population

### Context

ADR 62 establishes one server-owned, outcome-anchored population for the
Diagnose chart and inspector. The browser must not infer overlap, membership,
direction, support, rank, or denominators. Before this correction,
`frontend/diagnose-workstation.js` retained the last loaded projection while a
replacement request was pending. Queue and parameter-detail branches could
therefore present that prior population under the new clock label.

The predecessor was verified before code changes at exact base
`5055f4950bc4d14d9cfcb9a7bb3a9bd39184bb94`: all 43 frozen stories passed
through the no-fetch app. The server used
`mockups/revise-e2e.synthetic/harmonic.sqlite`, generated by
`scripts/gen_revise_e2e_db.py` from fixed seed 620; deterministic API reads used
the committed synthetic Diagnose payload. The source and rendered inventory
found no unrepresented behavior. The ledger delta is grounded in the user's
report: “fix this bug, unrelated basal slots showing up in sliced views.”

### Decision

A findings projection is renderable only when its loaded request key matches the
current findings-window key. Pending and failed replacements are inspector-wide
states evaluated before queue or detail rendering:

- Pending renders `Counting HH:MM–HH:MM…` with `data-loading="true"`.
- Failed renders `Findings unavailable for HH:MM–HH:MM. Choose another window to try again.`
  with `data-loading="false"`.
- Both keep SIFT enabled and preserve its pressed state, but withhold SIFT and
  crumb counts and all projection-backed advisory content.
- A parameter detail opened from the queue retains the projection's row id. A
  matching settled projection re-resolves that id; if absent, the depth remains
  open and renders `No findings in the selected window`.
- Late responses keep the existing request-key guard. A failed key suppresses an
  immediate retry loop and clears when a different window is selected.

The browser never compares slot or block times to decide membership. ADR 62's
one-population and server-ownership decision remains unchanged. The frozen
contract is `mockups/finding-evidence-routing.behavior.md`; S41 and S42 in
`frontend/diagnose-workstation-behavior.replay.mjs` are its vertical built-app
evidence.

### Safe-start provenance

`AGENTS.md` declares the no-fetch entrypoint and the generated synthetic
database. Issue 81 used that command with the user's authorized port-only change
to `28765` because ports `8765` and `18765` were occupied:

```sh
uv run harmonic serve --no-fetch \
  --db mockups/revise-e2e.synthetic/harmonic.sqlite --port 28765
```

No fetch path, credential source, real database, or personal health data was
used.

### Rendered evidence

The paired 1440×900 synthetic evidence is committed under
`docs/screenshots/issue-81/`. The `base-pending-queue-*` and
`revision-pending-queue-*` images are the strict before/after pair: both use the
same committed synthetic projection with its `05:30` basal row, and differ only
in the revision withdrawing that population under 15:00–21:00. The detail
images are complementary depth coverage, not a one-variable pair: the exact-base
generated database exposes a `07:00` basal detail while the projection fixture
exposes `05:30`. `revision-failed-*` shows the explicit unavailable state, and
`revision-settled-{absence-detail,queue}-*` shows the absent `05:30` detail and
the server-published `19:30 to 21:00` basal row. Queue and open-setting depths
were inspected in both themes. No overlap, clipping, new visual language, or
theme drift was observed.

### Consequences

The inspector may temporarily show less information, but it never attributes a
prior population to a new window. A failed request is explicit and recoverable
through another window selection. Whole-day findings and all server membership
rules are unchanged.
