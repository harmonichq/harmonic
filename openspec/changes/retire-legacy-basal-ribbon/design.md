# Design — Retire the legacy basal ribbon and revise its queue noun (#104)

This change records execution of already-locked boundaries. Deleting unreachable
source and applying an existing reader-facing term settle no new hard-to-reverse
product or architecture decision, so this record intentionally adds no ADR.

## Two lifecycle paths

The legacy basal coverage-ribbon cluster has lifecycle `none`: the root Vue
component uses the in-document template, and none of the cluster's setup exports,
refs, classes, route state, or URL state is consumed there. A closed source
inventory, not a behavior retirement sanction, proves its removal. This follows
the unreachable staging-entry precedent rather than the reachable stale-bookmark
retirement precedent.

The findings-queue noun has lifecycle `revise`: “Finding → evidence routing
(Diagnose + Verify)” is a shipped surface with a frozen behavior ledger and
app-only replay. The server publishes `support: {n, noun, run_days}` and the queue
painter reads that structure verbatim. The source of truth, fixture-only mirror,
generated frozen answers, and unit expectation therefore move in lockstep.

## Revise safe-start declaration

`AGENTS.md` declares the only allowed served command for this revision:

```sh
uv run harmonic serve --no-fetch --db mockups/revise-e2e.synthetic/harmonic.sqlite
```

The database is generated entirely by committed
`scripts/gen_revise_e2e_db.py` from fixed seed 620. The replay's deterministic API
reads use `mockups/diagnose-workstation.synthetic/payload.json`, generated by
`.claude/qa/gen_synthetic_fixtures.py` from a fixed seed. Base and revision
evidence used only these synthetic sources. No plain server, fetch path,
credentials, or real pump data is part of the change.

## Retirement boundary

The deletion is limited to the named basal tier, block-diff, coverage-ribbon, and
evidence-strip cluster and its transitive orphans. The source inventory owns the
retired identifiers and the complete 47-class set; it also protects the separate
live prompt-queue ribbon. Other root-component exports and unrelated dead-looking
shell selectors remain outside this ticket because their reachability was not
settled here.

The archived finding-evidence design study extracts the shell stylesheet, so its
stylesheet artifact is regenerated with the deletion. Its findings projection is
passed to the shipped queue painter whole. Once the projection publishes the
locked noun directly, the study preserves that noun unchanged and continues only
its rule-8 title respelling; retaining the support-object assignment keeps the
generated JSON key order byte-identical.

## Scope boundary against #102

#104 owns the findings-queue support noun in the Python projection, JavaScript
mirror, generated frozen answers, queue unit expectation, and archived design-
study adapter. #102 owns basal case-file wording and its manufactured demo source,
including `frontend/diagnose-workstation.js` and
`.claude/qa/gen_synthetic_fixtures.py`. This change does not generalize the noun
replacement into those owners or into engine-domain comments and docstrings.

## Verification design

The two proofs remain distinct:

1. The dependency-free source inventory fails naturally while any retired name,
   chart-builder export, or closed-set selector remains. It also asserts that the
   live prompt-queue ribbon alias remains singular.
2. The shipped-surface revision freezes the built-app replay before edits, confirms
   the queue row and existing ledger coverage, captures the base render, then
   repeats the same replay count and render after the lockstep noun change.

The projection generator and mirror comparison prevent backend/browser drift. The
design-study `--check` prevents stale extracted source or generated data. The fast
gate and public-tree checks protect the remaining repository and data boundary.
